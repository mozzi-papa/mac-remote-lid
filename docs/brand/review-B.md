# 독립 검토 B — 검사기와 브라우저 근거

검토 대상은 `website/index.html`과 공개 페이지 `https://kangunmo.github.io/mac-remote-lid/`입니다. Assessment A의 의견이나 결과는 읽지 않았습니다. 이번 검토는 브랜드 방향의 선호보다 규칙, 실제 스타일, 오탐, 접근성 근거를 분리합니다.

## 검사 결과

실행 명령은 `sh .agents/skills/impeccable/scripts/impeccable detect --json website/index.html`입니다. 원본 JSON은 `docs/brand/detector.json`에 보존했습니다. 최초 도구 출력이 잘려서 원본 파일 저장을 위해 다시 실행했습니다.

| 규칙 | 건수 | 해석 |
|---|---:|---|
| low-contrast | 8 | 의미 있는 텍스트 7건과 장식 글자 1건을 구분해야 합니다. |
| undersized-ui-text | 8 | 8–10px 기능 텍스트가 포함되어 있습니다. |
| tiny-text | 8 | 9–11px 본문 및 보조 정보이며 앞 규칙과 중복될 수 있습니다. |
| cramped-padding | 4 | 실제 패딩과 자식 위치를 확인하면 모두 수정 근거가 약합니다. |
| kicker-above-heading | 1 | 미리보기의 MAC REMOTE LID 라벨입니다. 접근성 결함과 같은 수준으로 취급하지 않습니다. |
| radial-halo | 1 | 어두운 제품 무대의 원형 그라데이션입니다. 스타일 규칙이며 기능 결함은 아닙니다. |
| 합계 | 30 | 서로 다른 사용자 문제 30개를 의미하지 않습니다. |

검사기의 모든 위치가 `website/index.html`, `line: 0`으로 반환되었습니다. 이 숫자는 실제 줄 번호가 아닙니다. 아래 CSS 선택자와 줄 번호로 위치를 보완했습니다.

## 본문색 실제 대비

공개 페이지의 브라우저 계산 스타일에서 `.hero-description`은 `rgb(96, 113, 129)`, 18px였습니다. `.build-note`도 같은 색이며 11px였습니다. `.preview-tag`, `.demo-settings > div`, `.demo-summary`의 실제 계산 색은 각각 CSS 값과 일치했습니다. 배경은 소스의 불투명한 가장 가까운 조상 배경을 사용했습니다.

sRGB 상대 휘도 공식으로 계산한 결과입니다. 본문 기준 4.5:1과 비교했습니다. 이미지와 안티앨리어싱 픽셀을 채집한 결과가 아닙니다.

| 위치 | 글자 / 배경 | 대비 | 판단 |
|---|---|---:|---|
| 주 본문 `.hero-description`, 일반 보조 본문 | #607181 / #f7f9fb | 4.764:1 | 통과합니다. 본문색 전체가 저대비라는 주장은 맞지 않습니다. |
| 기본 글자 `--ink` | #152a3b / #f7f9fb | 13.952:1 | 통과합니다. |
| 강조 글자 `--teal` | #246b61 / #f7f9fb | 5.938:1 | 통과합니다. |
| 미리보기 제목 막대 `.window-bar` | #667985 / #f8fafb | 4.324:1 | 일반 크기 텍스트 기준에 미달합니다. |
| `.preview-tag`, `.demo-label` | #81919b / #f8fafb | 3.107:1 | 9px 텍스트이며 기준에 미달합니다. |
| 설정 설명 `.demo-settings > div` | #788995 / #f8fafb | 3.452:1 | 11px 텍스트이며 기준에 미달합니다. |
| 복원 설명 `.demo-summary` | #84939d / #f8fafb | 3.020:1 | 11px 텍스트이며 기준에 미달합니다. |
| 안전 안내 제한 `.safety-footnote` | #607c73 / #edf3f1 | 4.039:1 | 12px 텍스트이며 기준에 미달합니다. |

실제 수정 우선순위는 안전 안내 제한과 복원 설명입니다. 이 문구는 제품이 무엇을 보장하는지 판단하는 데 필요합니다. 색만 진하게 바꾸어도 대비 문제를 해결할 수 있으며 브랜드 전체 팔레트를 바꿀 근거는 아닙니다.

## 우선 문제

### P1 — 중요한 제한 안내의 낮은 대비와 작은 크기

`website/styles.css:110`의 `.safety-footnote`는 원격 접속과 인터넷 연결을 보장하지 않는다는 핵심 제한을 4.039:1로 표시합니다. 모바일에서는 `website/styles.css:198`에 의해 11px가 됩니다. 4.5:1 이상으로 조정하고 최소 12–14px 수준에서 읽을 수 있도록 검토하는 것이 적절합니다.

`website/styles.css:78`의 `.demo-summary`도 복원 동작 설명을 3.020:1, 11px로 표시합니다. 같은 화면에서 기능 설명은 진한 글자와 충분한 크기로 통일하는 것이 필요합니다.

### P2 — 설치 판단 정보와 미리보기 표식이 작습니다

`website/styles.css:38`의 `.build-note`는 11px이며 모바일의 `website/styles.css:175`에서는 10px입니다. 공증 미적용 안내와 설치 전 확인 링크가 여기에 포함됩니다. `.preview-tag`와 `.demo-label`은 각각 `website/styles.css:62`, `website/styles.css:65`에서 9px입니다.

모바일의 설치 안내 세부 문구도 `website/styles.css:206`에서 11px입니다. 눈에 덜 띄는 장식 정보와 설치 결정을 위한 정보에 같은 축소 규칙을 적용하지 않는 편이 적절합니다. WCAG가 모든 텍스트에 절대 픽셀 하한을 정한다는 의미는 아닙니다.

### P2 — 브랜드 영문 이름이 세 형태로 노출됩니다

헤더에는 `RemoteLid`, 제품 무대에는 `REMOTE LID / FOR MAC`, 미리보기에는 `MAC REMOTE LID`가 노출됩니다. URL 및 내부 앱 경로의 `RemoteLid`는 기술 식별자이며 화면 브랜드와 별개로 유지할 수 있습니다. BI와 VI 문서에서는 한국어 제품명과 영문 보조 표기의 관계를 하나로 정의하는 것이 필요합니다.

### P2 — 설치 경로별 신뢰 설명이 다르게 들릴 수 있습니다

설치 명령 안내는 “보안 경고 없이”를 강조하고, 아래 수동 설치 안내는 공증 미적용과 출처 확인을 설명합니다. 실행 경로의 실제 동작을 이번 검토에서 검증하지 않았으므로 보안 결함으로 단정하지 않습니다. 다만 사용자는 설치 방식에 따라 앱의 신뢰 수준이 달라졌다고 읽을 수 있으므로, 경고 표시와 코드 서명 상태의 관계를 같은 영역에서 설명하는 편이 명확합니다.

## 오탐과 낮은 우선순위

- `.stage-wordmark`의 STAY AWAKE 글자는 `aria-hidden="true"`이며 장식입니다. 1.1:1 검출을 본문 대비 실패로 합산하지 않습니다. `website/styles.css:46`의 투명 색상 효과를 제거할 필수 근거가 아닙니다.
- `.product-stage`는 절대 위치 레이어를 담은 무대입니다. 자식 `.stage-topline`, `.stage-copy`, `.demo-window`, `.stage-bottom`이 개별 위치를 가집니다. 컨테이너 자체의 padding 0만으로 가장자리 밀착을 확정할 수 없습니다.
- `.window-bar`는 높이 37px, 수직 가운데 정렬, 좌우 14px 패딩을 사용합니다. border-bottom과 padding-bottom 0을 읽은 경고는 글자가 선에 붙는다는 근거가 아닙니다.
- `.safety-section`은 전체 폭 배경이며 자식 `.wrap`이 내용을 안쪽으로 제한합니다. 바깥 배경까지 좌우 패딩을 추가하면 의도한 전체 폭 구성을 바꿀 수 있습니다.
- `.faq-section`은 실제 브라우저 계산 스타일에서 `padding: 60px 0px 70px`였습니다. “border-top에 여백 없이 붙음”이라는 검출은 계산 결과와 모순되므로 오탐입니다.
- `kicker-above-heading`과 `radial-halo`는 스킬의 시각 규칙과 일치하는 검출입니다. 제품 무대의 조명과 앱 식별 라벨의 역할을 고려해 판단해야 하며, WCAG 실패처럼 취급하지 않습니다.
- 8–10px 라벨은 소스의 모바일 규칙까지 포함합니다. 공개 페이지 브라우저는 1558×1215에서 관찰했습니다. 모바일에서 직접 확인한 결과라고 표현하지 않습니다.

## 접근성 근거

소스에는 본문 바로가기, `lang="ko"`, 제목 구조, 섹션 제목 연결, 이미지 대체 텍스트, 장식 이미지의 빈 대체 텍스트가 있습니다. 토글은 실제 button에 `role="switch"`와 `aria-checked`를 제공하며, 상태 설명은 `aria-live="polite"`를 사용합니다. 복사 결과도 `aria-live`에 표시합니다.

`website/styles.css:7`에 링크, 버튼, summary의 `:focus-visible` 표시가 있으며, FAQ는 기본 details/summary를 사용합니다. `app.js`에는 `prefers-reduced-motion` 대응이 있습니다. 코드 존재만 확인했으므로 키보드 전체 흐름, VoiceOver 낭독, 동작 감소 설정에서의 실제 렌더가 검증되었다고 주장하지 않습니다.

## 실행 기록과 제한

- 공개 페이지는 ego-browser의 새 작업 공간 `원격지킴이 독립 검토 B`, ID 25의 p1에서 열었습니다. 전체 페이지 의미 구조 스냅샷과 계산 스타일을 확인했습니다.
- 제목에 `[Human]`을 추가하고 임시 script를 삽입해 `window.__impeccablePreflight === true`를 확인했습니다. 브라우저 내부 임시 변경이며 HTML 소스를 수정하지 않았습니다.
- Impeccable live-server를 직접 시작했고 PID 74072, port 8400을 받았습니다. 이후 detect.js 삽입 명령은 실행 시작 전에 “Control of this task space is with the user” 오류로 중단됐습니다. 제어를 임의로 회수하거나 다른 탭으로 우회하지 않았습니다.
- 따라서 detector overlay 실행, overlay 화면 표시, 콘솔 findings, 스크린샷을 확인하지 못했습니다. 사용자에게 보이는 overlay가 있다고 주장할 수 없습니다.
- `live-server stop --keep-inject`가 “Stopped live server on port 8400.”을 반환했습니다. 사용자가 실행한 서버는 종료하지 않았습니다. HTML 주입 제거 명령도 실행하지 않았습니다.
- 작업 공간 finish는 사용자 제어 중단 규칙 때문에 실행하지 못했습니다. 탭은 사용자 제어에 남아 있습니다. preflight 제목과 임시 스크립트는 해당 탭의 메모리에 남을 수 있으며 새로고침하면 사라집니다.
- `.impeccable/critique/ignore.md`는 없었습니다. 검토 A 결과는 보지 않았습니다. 임시 결과 파일은 만들지 않았으며 승인된 두 문서만 결과로 저장했습니다.

## 종합에 전달할 판단

본문 기본 색은 4.764:1로 통과하지만, 미리보기와 안전 안내의 일부 보조 문구는 통과하지 못합니다. 30건을 그대로 디자인 결함 수로 사용하지 않고, 중복과 장식 텍스트, 실제 여백 오탐을 제거한 뒤 우선순위를 정해야 합니다. 브랜드 정리는 영문 표기와 중요한 안내의 가독성을 먼저 고정하는 것이 근거에 맞습니다.

미확인 범위는 모바일 실제 렌더, 스크린샷 기반 시각 판단, 키보드와 VoiceOver 흐름, 설치 스크립트 실행입니다. 공개 사이트와 로컬 파일의 바이트 단위 동일성도 검증하지 않았습니다.
